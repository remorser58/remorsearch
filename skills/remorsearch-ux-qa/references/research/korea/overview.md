# 한국 리서치 라우터

한국 채널·사용자 조사용입니다. 규칙 기준일 2026-10-01, 외부 사실의 관찰됨·추론·미확인은 각 출처·확인일을 따릅니다. 안전·근거 규칙은 `references/shared/access-card.md`와 `references/shared/evidence-card.md`에 있습니다.

## 1. Phase 0: 세 스위치

| 스위치 | 읽기와 결과 |
| --- | --- |
| 한국어 보고 | 문구·제목만 바꿈. 제목 뒤 첫 절은 결론, 본문은 합니다체, 표는 개조식 |
| 한국 채널·사용자 리서치 | 이 라우터; 필요한 채널·질문·표지만 ID로 조회 |
| 한국 제품 QA | `references/persona-qa/kwcag-card.md`; 플랫폼 지도는 자동으로 읽지 않음 |

언어만 한국어이면 채널·법률·통계를 열지 않습니다. 커뮤니티 QA는 요청한 경우만 합니다. 제공된 URL/판/질문/기기/기간/자료/접근/키/권한을 반영하고 필요한 정보만 한 번에 묻습니다. standard 기본값과 작은 예산·quick 우선 규칙은 `references/research/workflow.md`를 따릅니다. 결합 실행은 현재 단계의 카드만 읽습니다.

## 2. Open when: 조건이 생길 때 조회

8절 표의 큰 파일은 항목 조회용(lookup-only)입니다. 스킬 폴더에서 `python3 scripts/ref.py <file> <section-id>`로 조회하며 ID 생략은 목록, 8 KB 초과는 하위 ID입니다. 채널은 `python3 scripts/ref.py platform naver-blog`로 봅니다. 법령·표준의 원문 확인 범위와 미검사는 별도로 적으며 이 라우터는 법률 적용을 판정하지 않습니다.

## 3. 자료와 접근

생산자가 이름·연락처·계정·결제·행 ID를 지우고 검토한 분석·설문·VOC·고객센터·자체 앱 콘솔 자료를 먼저 씁니다. 원래 출처 유형을 보존하며 리뷰 건수를 측정 비율로 바꾸지 않습니다. 윤리 심의는 기록이며 자동 승인이 아닙니다.

약관 status는 근거 상태이며 lift_requires로 해제를 정합니다. never는 페이지 금지, terms_check는 사용자 확인, written_permission은 확인·해당 읽기의 사전 서면 허락이 필요합니다. 겹친 항목(네이버 약관·카페 공지 등)은 각각 확인합니다. 에이전트는 확인을 만들지 않으며 날짜·문서·예산·중단은 접근 카드를 따릅니다.

채널 경로·중단을 조회하며 중단 뒤 다른 도구·주소로 회수하지 않습니다. App Store 공개 리뷰 피드는 닫혔고 승인된 자체 앱 콘솔은 별도 팀 자료입니다. 덜 잡힌 집단은 인터뷰·설문·팀 자료 공백으로 적습니다. 유튜브는 사용자 환경 키의 Data API만, 정책 검토 전 정성 근거만 씁니다. 키 없음 답변을 반복 질문하거나 채팅으로 키를 받지 않습니다. API 실패를 페이지로 대체하지 않으며 retention_until까지 지우거나 다시 읽습니다.

## 4. 사용자 언어와 수치

한국어부터 검색하고 실제 사용자 영어 용어로 확장합니다. 문맥·앞뒤 댓글로 뜻·극성을 확인하며 초성체·말투·호칭으로 연령·성별·능력을 추정하지 않습니다. 사전은 모호할 때 선택적으로 조회하고 not_checked를 허용합니다. lexicon.json에는 실제 읽은 용례만 남깁니다. 익명 사연은 narrative_unverified·존재 근거, 익명/IP 일부 닉네임은 스레드 단위입니다. 커뮤니티 추정 성별·연령·정치 성향을 개인·주장·페르소나에 붙이지 않습니다.

광고·보상·가상인물은 검증 후보이며 내돈내산·표시 없음은 독립성 근거가 아닙니다. 게시일 기준 표시 규칙·근거 카드의 감점/상한을 적용합니다. 수치는 모집단/표본/기간/기관/제품 관계의 출처 카드가 필요하며 상담/적발/글/별점 건수로 비율을 만들지 않습니다.

## 5. 보고

모드의 결론·발견·행동·커버리지 순서를 따릅니다. 연구는 ID/상태/출처 인용·수치/반대 근거 결과, QA는 판정/행동/미검사입니다. 미지원 인용은 부록, 가설·권고는 명시합니다. 0건 중단은 생략하며 약관·범위 밖·계획 공백·실제 중단을 나눕니다.

출처/도구/문맥/날짜/경로/약관/해제/예산/공백과 개인정보/요약/기한을 밝힙니다. 법적 적용은 해당 행의 확인 상태·법률가 판단, 모델은 제공사·지역·저장/학습 조건을 적습니다. gate만 상태를 쓰고 없는 명령은 수동·미검증입니다. 범위·수치·번역·인과를 검토하고 close로 임시 글/솔트를 지웁니다. 닫힌 영수증은 사용자 보관 결정까지 두되 API 기한이 우선합니다.

## 6. 완료 기준(Done when)

세 스위치와 깊이가 기록되고 필요한 ID만 조회함. 중단·불확실성·공백·예산·기한·반대 근거·수동 검증을 밝혔음. QA 두 표준은 별도 결과/범위이며 실제 개인정보와 무단 변경이 없음.

## 7. 실패 유형(Failure modes)

| 실패 | 조치 |
| --- | --- |
| 한국어 보고가 채널 전집을 불러옴 | 언어 스위치만 적용 |
| 키·원문·검증자가 없음 | 공급된 답변 반영, 공백/자기 검증 표시, 필요한 접근만 질문 |
| 상태로 약관 해제를 정함 | lift_requires와 항목별 사용자 확인 |
