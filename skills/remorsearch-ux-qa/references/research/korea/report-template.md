# [제품] UX 리서치 보고서

## 결론

발견을 최대 세 개, 다음 행동을 최대 세 개, 수집 범위를 한 줄로 적습니다. 제품팀이 쓰는 말로 과업과 다음 시험을 설명합니다.

1. **[주장 ID] · [gate 상태와 한국어 풀이].** [상황·과업·발견을 한 문장으로 씀.] [풀어 쓰기 뒤 짧은 인용 또는 수치; 출처: 채널, 날짜, 출처 ID.]
   Counter: [none_found | qualifies | contradicts] - [반대 근거 검색 결과와 요약; 검색어, 출처 또는 기록 ID].

**다음 행동**

1. [바꾸거나 시험할 행동; 주장 ID; 확신을 높일 관찰·측정.]
2. [필요할 때만 씀.]
3. [필요할 때만 씀.]

**수집 범위:** [읽은 페이지 수; 주요 중단; 보지 못했거나 시험하지 않은 것.]

작성 안내: 빈 칸과 불필요한 행동은 지웁니다. 본문에는 `supported_high`, `supported_medium` 주장을 씁니다. 상태와 반대 근거 검색 결과는 같은 입력 판의 gate 기록에서 가져옵니다. gate를 실행할 수 없으면 차단 이유를 밝히고 후보 주장은 부록에 둡니다. 만든 예제의 출처와 gate 결과는 fixture 데이터라고 밝히고 실제 실행 여부를 적습니다. 예제의 상태 값은 형식을 설명하며, synthetic 자료는 실제 연구 근거로 승격하지 않습니다.

## 발견

결론의 발견을 과업별로 설명합니다. 근거가 뒷받침하는 범위, 다음 시험, 현재 제품에 옮길 때의 한계를 적고 주장 ID와 상태를 붙입니다. 경험을 적은 글과 현재 화면에서 재현한 동작을 구분합니다. 경험의 존재를 뒷받침하는 상태만으로 사용자 비율·원인·개선 효과를 확정하지 않습니다.

## 수집 범위

- 질문, 제품·화면, 조사 날짜·기간, 조사 깊이, 다룬 축·생략한 축.
- 검색 수와 예산, 읽은 페이지 수와 예산, 확장 횟수, 호스트별 읽기 수. 고유 URL, 읽기, 반복 호출·사전 점검을 따로 셈.
- 실제로 쓴 도구, 첫 검색 전에 읽은 접근 카드, 브라우저 맥락, 실행할 수 없었던 도구. 독자·검토자에게 필요한 근거·접근 카드를 작업 지시에 함께 전달함.
- 읽은 채널·공식 출처·팀 자료, 덜 잡힌 상황, 현재 제품에서 시험하지 않은 동작.

깊이별 범위: quick은 1–2축·검색 12개 이하·읽기 15개 이하·확장 없음. standard는 필요한 축 4개 이하·축마다 검색어 4개 이상·검색 40개 이하·읽기 40개 이하(호스트당 10개)·확장 1회. deep은 기본 축 전체·축마다 검색어 8개 이상·검색 120개 이하·읽기 200개 이하(호스트당 30개)·확장 최대 2회. 계획과 실제 수를 함께 적습니다.

### 1.1 문체 자체 점검

합니다체로 통일하고 한 문장에 판단 하나를 담습니다. 사용자, 과업, 근거, 출처, 주장, 불편 지점, 수집 공백을 같은 뜻으로 씁니다. 관찰됨은 출처에 직접 있는 내용, 추론은 관찰을 잇는 판단, 미확인은 확인할 자료가 남은 내용입니다. 확신은 근거 상태로 나타냅니다. 본문에서 불필요한 피동·긴 명사 나열·직역 표현을 줄이고, 인용·숫자·ID·URL·코드·자리표시는 보존합니다. 수정 뒤 주장 범위와 출처 연결을 작성자가 다시 확인합니다.

### 1.5 날짜와 수치 자체 점검

날짜는 YYYY-MM-DD, 본문 시각은 KST YYYY-MM-DD HH:mm, 영수증 시각은 시간대가 있는 ISO 형식으로 씁니다. 게시일·읽은 날·유효 시점을 구분합니다. 수치에는 n·모집단·기준 시점·출처를 붙입니다. 글·후기·좋아요 수를 사용자 비율로 옮기지 않습니다. 비중 출처가 맞지 않으면 null로 둡니다.

## 완료 점검

- 결론이 첫 절이며 발견·다음 행동은 각각 최대 세 개입니다. 주장 ID·상태, 출처가 있는 인용·수치, `Counter: <outcome> - <summary>`, 수집 범위 한 줄이 있습니다.
- 모든 인용 주장에 gate 상태가 있고, 지원되지 않은 사실 주장은 부록에 있습니다. 원인 가설과 제안은 추론으로 표시했습니다.
- QA에서 가져온 P0/P1에는 캡처 영수증과 2차 확인이 있습니다. 연구만 한 보고서는 해당 없음으로 적습니다.
- 세그먼트로 인터뷰를 준비할 수 있고, 비중은 맞는 출처가 없으면 null입니다. 제안마다 행동 변화·감수할 점·확신을 높일 시험이 있습니다.
- 중단은 0보다 큰 행만 적었습니다. Figma·법률 항목은 필요한 경우만 있습니다. 이름·닉네임이 없고, 시험하지 않은 것을 밝혔습니다. 문체·인용·날짜·수치를 작성자가 점검했습니다.
