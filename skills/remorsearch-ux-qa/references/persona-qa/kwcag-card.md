# 한국 제품 QA 안전·보고 카드

한국 제품 QA의 시나리오 선택 전에 읽습니다. 한국어 보고만 요청하면 이 카드를 열지 않습니다. 세부 기준은 `references/persona-qa/kwcag-2.2.md` 5.1, 7과 해당 번호만 조회합니다. 페르소나·검증자에게 이 카드를 전달합니다.

## 1. 테스트 신원과 중단

팀이 준 테스트 신원·번호·주소·인증서만 씁니다. 실제 주민등록번호, 전화번호, 카드·계좌 번호, 비밀번호, 공동인증서를 입력하지 않습니다. 결제·가입·주문·게시는 별도 권한이 필요합니다.

| 환경/흐름 | 검사 범위 |
| --- | --- |
| 운영 인증 | 인증 화면이 열리는 데까지; 통과는 미검사 |
| 운영 SMS 인증번호 | 번호 요청 전 중단 |
| CAPTCHA | 위젯 표시에서 중단; 풀거나 기다리지 않음 |
| 운영 결제 | 결제창 진입 버튼 또는 결제 확정 전 중단 |
| 공동인증서·보안 키패드 | 인증서 선택 전 또는 키패드 화면까지; 실제 비밀번호 금지 |
| 승인된 스테이징 모의 인증·테스트 결제 | 별도 테스트 데이터 권한 범위 안에서 완료·실패·복귀까지 검사 |
| 공개 주소 검색 | 테스트 주소로만 검사 |

멈춘 단계와 그 뒤의 화면·확정·서명은 미검사로 적습니다. 제3자 위젯도 접근성 관찰 대상입니다. 수정 층은 제품 연동 코드와 제공사 위젯으로 나눕니다. 제품 팀이 허용 출처를 정하며 `drivers/web/README.md`의 --allow-origin을 필요한 절만 조회합니다. 차단된 출처, iframe, 브라우저 밖 창, 앱 전환은 도구가 다루지 못하면 미검사입니다.

팝업·레이어·앱 전환: 예고, 팝업 차단 안내, 창 제목, 열 때 내부 초점, 닫기와 복귀 초점, 입력값·진행 단계 보존을 확인합니다. 인증 수단: 기억·옮겨 적기·퍼즐에만 기대지 않는 대안, 붙여넣기·자동 채움·비밀번호 관리자 허용 여부를 기록합니다. 시나리오는 과업의 접근 수단·진입 맥락만 쓰며 나이·장애·말투로 능력을 추정하지 않습니다.

## 2. 관찰 범위

화면 크기 에뮬레이션은 실제 기기·그립·키보드 가림·안전 영역·스크린리더 검사가 아닙니다. 터치 결정은 스크린샷으로 하고 기술 검사에서 DOM·접근성 트리·초점을 봅니다. 채널·근거와 실제 보조기술 확인 범위를 적습니다. 매 단계 입력값을 확인하고 실패 제출 뒤 첫 오류 필드의 초점·invalid 상태·오류 연결을 검사합니다.

## 3. 두 기준을 따로 보고

`references/persona-qa/qa-report-template.md`의 발견 카드에 KWCAG 2.2 항목과 WCAG 2.2 SC를 별도 열로 적습니다. 각 기준에 번호·제목·판·출처와 확인 상태, 결과, 검사 화면·조건·미검사 범위를 따로 씁니다. 두 결과를 서로 대신 쓰지 않습니다.

결과는 해당 항목의 실패/문제 미관찰, 일부(이유), 대응 항목 없음, 미검사, 미확인으로 적습니다. 공식 원문 대조 또는 미러 확인 여부를 밝혀 확인 상태를 실제 읽기에 맞춥니다.  심각도 P0-P3는 사용자·제품 영향으로 정하며 필수/바람직/A/AA 수준으로 정하지 않습니다.

대비 PC-01은 WCAG 1.4.3 기준입니다. KWCAG 5.4.3의 확대 완화는 별도 판단입니다. 24 CSS px나 섬광 선별 검사만으로 KWCAG 충족을 판정하지 않습니다. 항목 예외·대응은 전체 문서에서 번호로 조회합니다.

보고서는 해당 화면·조건의 커버리지와 관찰됨·추론·미확인을 밝힙니다. 사용자 비율, 표준 준수 인증 또는 법 준수 판정을 하지 않습니다. 스크린리더·음성 제어·인앱·운영 인증/결제 미검사 범위와 시간 제한(초)을 적습니다. 앱 화면의 KWCAG 인용은 참고 범위이며 법적 적용은 이 카드로 판정하지 않습니다.
